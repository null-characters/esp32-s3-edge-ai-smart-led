```
┌─────────────────────────────────────────────────────────────┐

├─────────────────────────────────────────────────────────────┤
│                                                             │

│  │ LD2410   │  检测到有人进入                              │

│       │                                                    │
│       ↓                                                    │
│  ┌──────────┐                                              │

│       │                                                    │
│       ↓                                                    │
│  ┌──────────┐                                              │
│  │ MQTT     │  node/{id}/radar/status                     │

│  └────┬─────┘                                              │
```

### LLM Prompt 上下文注入

```python
# Agent Backend 上下文注入示例

def build_system_prompt(radar_state, sound_state, time_context):
    """
    构建带上下文的系统 Prompt
    """
    base_prompt = """你是"家电小精灵"，一个友好的智能家居助手。
你的职责是帮助用户控制灯光，并提供温馨的交互体验。

当前设备状态：
- 雷达状态：{radar_state}
- 声音场景：{sound_state}
- 时间：{time_context}

请根据用户状态主动提供帮助，但不要过于频繁打扰用户。
回复时请输出 JSON 格式。"""
    
    return base_prompt.format(
        radar_state=radar_state,      # "有人近距离停留"
        sound_state=sound_state,      # "键盘敲击声"
        time_context=time_context     # "晚上 9 点"
    )
```

### 多设备唤醒选主算法

```
┌─────────────────────────────────────────────────────────────┐
│                    唤醒选主算法                              │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  1. 设备 A、B 同时检测到唤醒词                              │
│                                                             │
│  2. 各设备上报音频能量到 MQTT:                              │
│     election/{room_id}/vote                                 │
│     {"device_id": "A", "energy": 0.85}                      │
│     {"device_id": "B", "energy": 0.72}                      │
│                                                             │
│  3. 边缘服务器收集所有投票（500ms 窗口）                    │
│                                                             │
│  4. 选主：能量最高的设备胜出                                │
│     winner = max(devices, key=lambda d: d.energy)           │
│                                                             │
│  5. 广播选主结果:                                           │
│     election/{room_id}/result                               │
│     {"winner": "A", "devices": ["A", "B"]}                  │
│                                                             │
│  6. 胜出设备 A 建立WebSocket连接，执行对话                  │
│     其他设备 B 进入待机状态                                 │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 验收标准

| 检查项 | 验收标准 |
|--------|---------|
| 雷达触发 | 用户停留 > 3s 触发问候 |
| 问候频率 | 同一用户 5 分钟内不重复问候 |
| 声音分类 | TFLM 分类准确率 > 85% |
| 场景联动 | 键盘声 → 专注模式自动触发 |
| 多设备选主 | 能量高者胜出，延迟 < 500ms |

---

## 风险与缓解

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|---------|
| 误触发问候 | 高 | 中 | 停留时间阈值 + 冷却时间 |
| 声音分类错误 | 中 | 中 | 置信度阈值 + 多帧确认 |
| 多设备竞争 | 低 | 中 | 选主算法 + 超时重选 |
